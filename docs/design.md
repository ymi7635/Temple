# 視覺重構紀錄

目前交付已改為 Vercel 純靜態前端，不包含後台、登入或 API。下文的原有架構盤點是歷史紀錄；現行啟動與活動維護方式以 README.md 為準。

盤點日期：2026-11-04（台北時間）。

## 原有架構與功能

React + Vite + React Router，GSAP、Three.js 已安裝，沒有 TypeScript／ESLint／測試框架。首頁有宮名、水面倒影、近期活動、參香查詢、活動列表、宮廟簡介及聯絡資訊。後台是單一未認證頁，能管理活動與上傳海報；API 依附 Vite 開發外掛，正式打包後沒有後端。資料放在公開 `public/data/events.json`，草稿也可能經直接下載取得。

保留 React／Vite、既有活動欄位與表單錯誤提示、JSON 寫入策略、參香查詢及聯絡入口。改建後端生命週期、管理者認證、公開資料路徑與所有前台版面。沒有為配合技術清單而另外引入 Tailwind、TypeScript、Express 或 React Three Fiber。

視覺問題是依程式碼與樣式盤點所得，非已完成實際瀏覽器評分：紫竹／青綠與水面倒影未呼應一炷香方向；內容主要採重複區塊，缺乏編輯式層次；首屏沒有明確的資訊入口；社群連結缺乏品牌圖示，部分帳號為推測；沒有可驗證的宮廟攝影；管理後台顯示未實作頁籤且沒有登入保護。

## 兩種視覺概念

| 決策項目 | A：墨色香境（採用） | B：廟埕光影 |
| --- | --- | --- |
| 首屏 | 100px 導覽、左右約 1:1 非對稱構圖；左宮名與文字，右細香／煙霧；底部閱讀提示 | 滿版本宮廟埕照片，宮名置於左下，右側窄直欄提供交通與活動 |
| 配色 | 暖黑 #171411、米白 #F5F0E7、朱紅 #852F2A、暖金 #C4A36A；朱紅集中一個查詢區 | 以米白為主，照片自然光為視覺重心；黑字與朱紅小面積導覽標記 |
| 文字 | 宋體大標 54–118px、內文 16–18px，細英文索引與章節號 | 橫向大字、攝影說明、小尺寸日期；偏文化刊物 |
| 介紹 | 左標題、右內文，主祀以線性資料列呈現 | 圖片佔 2/3，側欄介紹沿革，需實際歷史資料 |
| 活動 | 紙色底、橫向篩選；有封面時呈 3/2/1 欄，無資料有正式空狀態 | 以照片與日期交錯的全寬清單 |
| 手機 | 香意象退到文字側後方，單欄；選單獨立展開 | 照片縮成上半屏，下半屏宮名與交通入口 |
| 動畫 | 約 4 秒煙霧開場；標題分段揭露、區塊進場、閱讀進度 | 光線揭露與輕微照片視差；開場後立即完整呈現照片 |
| 高級感 | 字距、留白、材質色差與細線形成秩序 | 攝影品質決定主要觀感 |
| 宮廟辨識 | 香、朱印、宋體；不虛構建築外觀 | 本宮建築與生活紀錄最有辨識力 |
| 可讀性 | 深淺段落交替，主內容不壓在煙霧上 | 必須處理照片亮部與文字對比 |
| 工程可行性 | 現有素材足夠完成意象版；可替換正式照片 | 目前缺少授權照片，不宜用其他宮廟或生成照片冒充 |

採 A，原因是可在缺少正式實景素材的情況下完整建立一致設計系統，同時保持安定的宗教文化氣質。B 保留為取得正式攝影後的方向，未製作假照片補空缺。

## 內容與互動

首頁順序是香境 → 宮廟介紹 → 活動 → 參香查詢 → 參拜交通。導覽只有四個可用入口。活動提供獨立詳情頁，內容由專案 JSON 在建置時產生公開靜態檔，不包含後台、登入、會員或購物功能。

動畫只是輔助，頁面內容不依賴 Three.js。開場有 session 記憶、略過、Escape、重播、降低動態、手機備援與失敗 watchdog。背景在播放期間 inert，結束後解除；原生 scrollbar 不變。桌機自訂游標只用於精細指標，觸控及表單維持原生操作。
